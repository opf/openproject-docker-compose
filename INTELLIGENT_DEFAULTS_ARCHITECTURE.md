## Component 3: Engine Implementation

### Default Resolution Order (Precedence)
1. **User Input** (highest priority - user explicitly entered value)
2. **Dynamic Defaults** (layout.yml dynamic_defaults based on previous responses)
3. **Probe Defaults** (.defaults.yml from system detection)
4. **Static Defaults** (layout.yml default field)
5. **Type Defaults** (engine defaults: text="", confirm=true)

### Processing Flow
```
1. Load layout.yml
2. Check metadata.defaults_file field
3. If specified, load defaults file (config_TUI.defaults.yml)
4. For each step:
   a. Evaluate conditions (skip if not met)
   b. Calculate dynamic default based on previous responses
   c. Apply probe default override if available from defaults_file
   d. Fall back to static default from layout.yml
   e. Present to user with calculated default
   f. Store user response for future dynamic defaults
```

### Engine Resolution Logic
```python
def resolve_default_value(step, previous_responses, probe_defaults):
    """Resolve default value with precedence handling."""
    
    # 1. Check for dynamic defaults based on previous responses
    if 'dynamic_defaults' in step:
        for dynamic_rule in step['dynamic_defaults']:
            if evaluate_condition(dynamic_rule['condition'], previous_responses):
                return {
                    'value': dynamic_rule['value'],
                    'source': 'dynamic',
                    'reason': dynamic_rule.get('reason', 'Based on previous selections')
                }
    
    # 2. Check probe defaults from defaults_file
    step_id = step['id']
    if probe_defaults and step_id in probe_defaults.get('defaults', {}):
        probe_default = probe_defaults['defaults'][step_id]
        return {
            'value': probe_default['value'],
            'source': 'probe',
            'reason': probe_default.get('reason', 'Based on system detection')
        }
    
    # 3. Fall back to static default in layout
    if 'default' in step:
        return {
            'value': step['default'],
            'source': 'static',
            'reason': 'Layout default'
        }
    
    # 4. Type-based defaults
    return {
        'value': get_type_default(step['type']),
        'source': 'type',
        'reason': 'Engine default'
    }
```

## Implementation Benefits

### 1. **Intelligent System Adaptation** 🧠
- Automatically detects optimal settings for the target system
- Reduces configuration errors by suggesting appropriate values
- Adapts to development vs production environments

### 2. **Context-Aware Defaults** 🎯
- Database port automatically matches database type selection
- SSL configuration adapts to environment type
- Resource allocation based on actual system capabilities

### 3. **Separation of Concerns** 🏗️
- Layout defines UI flow and logic
- Probe file contains environment-specific overrides
- Engine handles intelligent resolution

### 4. **Maintainability** 🔧
- System admins can provide custom .defaults.yml files
- Layout designers focus on user experience
- Probe logic is separate and testable
